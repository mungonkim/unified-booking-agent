# 기술 스택

이 문서는 사용자가 아니라 Agent(Requirement/Architecture 논의 과정)가 작성한다.
사용자는 기술을 선택하지 않는다 — 요구사항을 말하면 여기서 근거와 함께 기술이 정해진다.

## 선정 결과

| 영역 | 선택 |
|------|------|
| 언어/런타임 | Python 3 + asyncio |
| 브라우저 자동화 | Playwright (async, Chromium, persistent context) |
| 자연어 파싱 | Anthropic API (`anthropic.AsyncAnthropic`, tool-use 강제 JSON 추출), 모델 `claude-haiku-4-5-20251001` |
| 설정/시크릿 | `python-dotenv` + `.env` |
| 패키지 관리 | `uv` (venv 생성/실행), 단 pip 미포함이라 `uv pip install --python .venv/Scripts/python.exe` 사용 |
| 배포 환경 | 로컬 실행 (개인 PC), 서버 배포 없음 |

## 선정 기준

**적용된 기준**: 간단한 개인용 자동화 도구 — 개발 속도와 실제 브라우저 조작 정확도가 우선, 확장성/동시성은 후순위.

| 상황 | 우선 고려 요소 |
|------|----------------|
| 간단한 MVP | 개발 속도 |
| AI 기능 포함 | Python / AI 라이브러리 지원 |

## 선정 이유

- 네이버 예약 페이지는 로그인/쿠키 세션 유지가 필요한 SPA라 실제 브라우저 렌더링이 필수 → Playwright
- 업종마다 페이지 구조가 다르고 사용자는 자연어로 질문하고 싶어함 → LLM 기반 슬롯 추출(Claude tool-use) 필요
- 개인 1인 사용, 트래픽/동시성 없음 → 별도 백엔드/DB/배포 파이프라인 불필요, 단일 Python 스크립트로 충분

## 검토했던 대안

| 대안 | 장점 | 이 프로젝트에서 채택하지 않은 이유 |
|------|------|-----------------------------------|
| Selenium | 성숙한 생태계 | Playwright 대비 async 지원·auto-wait가 약해 SPA 대응에 불리 |
| requests/BeautifulSoup으로 HTML 직접 파싱 | 가볍고 빠름 | 네이버 예약 페이지는 클라이언트 렌더링(SPA)이라 정적 파싱 불가 |
| 정규식/키워드 기반 질의 파싱 | 외부 API 불필요 | 업종·표현이 매우 다양해 자연어 이해가 필요, LLM이 압도적으로 안정적 |

## 재검토 트리거

- 여러 사용자가 동시에 쓰는 서비스로 확장 → API 서버화, 세션/브라우저 인스턴스 격리, DB 도입 재검토 필요 (지금은 명시적으로 보류 중)
- 네이버 예약이 아닌 다른 예약 플랫폼(카카오 등) 지원 요구 발생 → 사이트별 어댑터 계층 분리 검토
